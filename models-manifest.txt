# Model manifest for the video_gen image serverless worker.
#
# Format (tab-separated): <models subdir>\t<filename>\t<URL>[\t<sha256>]
# Consumed by populate-volume.sh at worker boot (VOLUME_AUTOPOPULATE=true):
# files land in /runpod-volume/models/<subdir>/<filename>, which is exactly the
# layout extra_model_paths.yaml exposes to ComfyUI.
#
# Every URL is pinned to an immutable Hugging Face commit revision and every file
# has a pinned sha256 (the LFS oid). `main` is forbidden: populate-volume.sh
# rejects a URL without /resolve/<40-hex-commit>/ and fails with a readable
# error, so a non-pinned manifest never silently downloads moving weights.
# Approximate sizes: FLUX.2 klein set ~16.1 GB, Qwen-Image-Edit set ~30.2 GB,
# Qwen-Image-2512 t2i file ~20.4 GB (it reuses the Qwen-Image text encoder and
# VAE of the edit set), full set ~66.7 GB. Attach a network volume of at least
# 100 GB (the old 60 GB minimum is no longer enough: ComfyUI outputs and
# temporary files also need room, and the volume should carry future models).
#
# Snapshot of the three commercial (Apache-2.0) models used by the keyframe stand:
#   - FLUX.2 klein 4B        — text-to-image, t2i graphs
#   - Qwen-Image-2512        — text-to-image, t2i graph (Qwen-Image)
#   - Qwen-Image-Edit-2511   — instruction/mask editing, edit graphs
# They share nothing except the qwen-image VAE/text-encoder pair is used by both
# Qwen models, and FLUX.2 klein has its own Qwen3-4B text encoder and FLUX.2 VAE.
#
# To add a model: add its files here with a pinned /resolve/<commit>/ URL and
# sha256, run populate-volume.sh, then add the graph template to the
# `image_models` catalog in video_gen (see README "Model catalog graphs").
# Filenames below are the names the ComfyUI graphs must reference; keep them in
# sync with `image_models.model_files[].path`.
